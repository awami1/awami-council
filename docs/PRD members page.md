# وثيقة متطلبات المنتج (PRD)

## تحسين صفحة الأعضاء — alawami.site

> الإصدار: 1.0
> التاريخ: مارس 2026
> المشروع: الموقع الرسمي لعائلة العوامي
> المسؤول: عبدالله (مجلس عائلة العوامي)
> الحالة: قيد المراجعة

-----

## 1. نظرة عامة

### 1.1 الهدف

إصلاح وتحسين صفحة إدارة الأعضاء في لوحة التحكم، بما يشمل: إصلاح خلل الاستيراد من Excel الذي لا يحفظ البيانات فعلياً، تحسين موثوقية زر الحفظ، تحديث مسميات حالات العضوية لتعكس الواقع التشغيلي، تحسين التحقق من البيانات عند إضافة عضو، وتحسين تجربة الاستخدام العامة للجدول والبحث والفلترة.

### 1.2 المشكلة الحالية

- **الاستيراد من Excel لا يحفظ فعلياً**: عند استيراد ملف Excel، البيانات تُعالج وتظهر في الواجهة لكنها تُحفظ في `localStorage` فقط عبر `saveDB()` — لا تصل لقاعدة البيانات (MySQL). عند تحديث الصفحة أو الدخول من جهاز آخر، البيانات المستوردة تختفي
- **زر الحفظ أحياناً لا يستجيب**: آلية حماية الطلبات المكررة (Request Deduplication) في `index.php` تمنع إعادة الإرسال إذا علق طلب سابق — الزر يبدو معطلاً
- **مسميات الحالات لا تعكس الواقع**: الحالات الحالية (نشط / معفي / غير نشط) لا تتوافق مع المصطلحات المستخدمة فعلياً في إدارة المجلس. حالة “معفي” غير مطلوبة بالكامل
- **التحقق من البيانات ضعيف**: عند إضافة عضو، التحقق يقتصر على أن الاسم ليس فارغاً — لا يوجد فحص لصيغة الجوال أو كشف للأسماء المكررة
- **حقول غير ضرورية**: حقلا “رقم الهوية” و”الفرع العائلي” في نافذة إضافة العضو غير مستخدمين فعلياً
- **الجدول والبحث يحتاجان تحسين**: تجربة الاستخدام العامة للجدول وأدوات الفلترة تحتاج تطوير

### 1.3 الحل

إصلاح مسار الاستيراد ليمر عبر الـ API الفعلي (`MemberService`)، إضافة خطوة مراجعة قبل الحفظ، معالجة مشكلة تعليق الطلبات، تحديث حالات العضوية في كامل النظام (قاعدة بيانات + Backend + Frontend)، تحسين التحقق ونافذة الإضافة، وتحسين شكل الجدول وتجربة البحث.

### 1.4 المستخدمون المستهدفون

|الفئة          |الوصف                                                      |
|---------------|-----------------------------------------------------------|
|**مدير الموقع**|يستورد أعضاء من Excel، يضيف أعضاء يدوياً، يدير حالات العضوية|

## 2. نطاق العمل

### 2.1 ✅ ما يشمله هذا PRD

- إصلاح الاستيراد من Excel ليحفظ في قاعدة البيانات فعلياً
- إضافة خطوة مراجعة وتعديل قبل حفظ الاستيراد
- إصلاح مشكلة زر الحفظ المتقطعة
- تغيير حالات العضوية: مشترك / منقطع / غير مشترك
- حذف حالة “معفي” من كامل النظام (عضوية + دفعات)
- تحسين التحقق من البيانات عند إضافة/تعديل عضو
- إزالة الحقول غير المطلوبة من نافذة الإضافة
- تحسين شكل جدول الأعضاء
- تحسين تجربة البحث والفلترة

### 2.2 ❌ ما لا يشمله هذا PRD

- نظام هوية الأعضاء والصفحة الشخصية (تم في المرحلة الأولى)
- إضافة أعمدة أو حقول جديدة لقاعدة البيانات
- تغييرات على الصفحة العامة (الموقع الخارجي)
- تغييرات على أقسام أخرى في لوحة التحكم (الرسوم، اللجان، الفعاليات)

## 3. التعديلات على قاعدة البيانات

### 3.1 تعديل جدول: members — عمود الحالة

تغيير قيم ENUM لعمود `status`:

```sql
-- MySQL
ALTER TABLE members 
  MODIFY COLUMN status ENUM('مشترك','منقطع','غير مشترك') NOT NULL DEFAULT 'مشترك';

-- ترحيل البيانات الموجودة
UPDATE members SET status = 'مشترك' WHERE status = 'نشط';
UPDATE members SET status = 'غير مشترك' WHERE status = 'غير نشط';
UPDATE members SET status = 'مشترك' WHERE status = 'معفي';
```

```sql
-- SQLite (لا يدعم ALTER ENUM — يتطلب إعادة إنشاء الجدول)
-- تحديث CHECK constraint:
CHECK(status IN ('مشترك','منقطع','غير مشترك'))
```

**ملاحظات:**

- الأعضاء بحالة “معفي” يُرحّلون إلى “مشترك” كقيمة افتراضية آمنة
- حقلا `status_override` و `status_override_note` الموجودان حالياً يبقيان كما هما — لا يتأثران
- القيمة الافتراضية تتغير من `'نشط'` إلى `'مشترك'`

### 3.2 تعديل جدول: payments — إزالة حالة معفي

```sql
-- ترحيل سجلات الدفع بحالة "معفي" إلى "لم يدفع"
UPDATE payments SET status = 'لم يدفع' WHERE status = 'معفي';
```

**ملاحظات:**

- لا حاجة لتعديل ENUM في جدول payments لأن الحالات (`مدفوع` / `لم يدفع`) تبقى كما هي
- فقط نُرحّل السجلات الموجودة بحالة “معفي”

## 4. إصلاح الاستيراد من Excel

### 4.1 المشكلة التقنية

الملف `admin-import.js` (سطر 61) يضيف الأعضاء المستوردين مباشرة في ذاكرة المتصفح:

```javascript
// الكود الحالي — المشكلة
State.getMembers().push(newMember);  // ذاكرة فقط
saveDB();  // localStorage فقط — لا يصل لقاعدة البيانات
```

بينما “إضافة عضو” اليدوية تمر عبر `MemberService.saveMember()` الذي يرسل للـ API:

```javascript
// المسار الصحيح (إضافة عضو)
MemberService.saveMember(id, data);  // → POST /api/members.php → MySQL
```

### 4.2 الحل المطلوب

**المسار الجديد للاستيراد:**

```
قراءة Excel → معالجة البيانات → عرض جدول مراجعة → المستخدم يراجع ويعدل → حفظ عبر API
```

**التفاصيل:**

1. **قراءة الملف ومعالجته** — يبقى كما هو (XLSX.js)
1. **عرض خطوة المراجعة** — جدول بكل السجلات المعالجة قبل الحفظ:
- تمييز الأعضاء **الجدد** باللون الأخضر
- تمييز الأعضاء **الموجودين** (تحديث) باللون الأصفر
- تمييز **المتجاهلين** باللون الرمادي مع سبب التجاهل
- إمكانية **حذف** أي سجل من القائمة قبل الحفظ
- إمكانية **تعديل** الاسم أو الجوال مباشرة في الجدول
1. **الحفظ عبر API** — عند الضغط على “حفظ الكل”:
- `POST /api/members.php` لكل عضو جديد
- `PUT /api/members.php?id=x` لكل عضو موجود (تحديث)
- عرض شريط تقدم (progress bar) أثناء الحفظ
- معالجة الأخطاء — إذا فشل طلب يُعرض بوضوح
1. **إزالة `saveDB()` بالكامل** من ملف الاستيراد
1. **تسجيل العملية** في `logAudit()`

### 4.3 تعديلات نافذة الاستيراد (modal-import-excel)

النافذة الحالية تحتوي فقط على:

- زر اختيار الملف
- منطقة عرض نتيجة المعالجة
- زر “إغلاق”

**المطلوب إضافته:**

- جدول المراجعة بعد المعالجة (بدل النص الملخص فقط)
- زر **“حفظ الكل”** في footer النافذة — يظهر فقط بعد المعالجة
- زر **“إلغاء”** يتجاهل كل البيانات المعالجة
- حالة loading على زر الحفظ أثناء الإرسال (spinner + تعطيل)

## 5. إصلاح زر الحفظ

### 5.1 المشكلة التقنية

في `admin/index.php` يوجد نظام حماية من الطلبات المكررة:

```javascript
// الكود الحالي
var dedup = (method === 'POST' || method === 'PUT');
var dedupKey = method + ':' + url;
if (dedup && _pending.has(dedupKey)) {
    return _pending.get(dedupKey);  // ← يرجع نفس Promise المعلق
}
```

**المشكلة**: إذا طلب POST سابق علق (شبكة بطيئة / خطأ بدون رد) — أي ضغطة لاحقة على زر الحفظ ترجع نفس الـ Promise المعلق. الزر يبدو وكأنه لا يستجيب.

### 5.2 الحل المطلوب

```javascript
// إضافة timeout للطلبات المعلقة
var DEDUP_TIMEOUT = 10000; // 10 ثواني

var promise = (async function() {
    // ... الطلب الحالي
})().finally(function() { _pending.delete(dedupKey); });

// Timeout — حذف الطلب من القائمة بعد 10 ثواني
if (dedup) {
    _pending.set(dedupKey, promise);
    setTimeout(function() { _pending.delete(dedupKey); }, DEDUP_TIMEOUT);
}
```

**بالإضافة:**

- إضافة حالة loading على زر الحفظ (spinner + تعطيل) عند الضغط
- إعادة تفعيل الزر بعد نجاح أو فشل الطلب
- يُطبق على كل أزرار الحفظ في نوافذ لوحة التحكم (ليس فقط الأعضاء)

### 6.1 الحالات الجديدة

**ملاحظات:**

- حالة “معفي” تُحذف بالكامل — لا يوجد استثناء يدوي للدفع

## 7. تحسين نافذة إضافة العضو

### 7.1 إزالة الحقول

تُزال من الواجهة فقط — تبقى في قاعدة البيانات:

|الحقل        |المعرف     |السبب           |
|-------------|-----------|----------------|
|رقم الهوية   |`mm-idnum` |غير مستخدم فعلياً|
|الفرع العائلي|`mm-family`|غير مستخدم فعلياً|

**الحقول المتبقية بعد التعديل:**

1. الاسم الكامل * (مطلوب)
1. رقم الجوال
1. تاريخ الانضمام
1. الحالة (مشترك / منقطع / غير مشترك)
1. ملاحظات

### 7.2 تحسين التحقق من البيانات (Validation)

**الوضع الحالي**: فقط `validateRequired('mm-name')` — يتحقق أن الاسم ليس فارغاً.

**المطلوب:**

|الحقل |التحقق                                          |رسالة الخطأ                              |
|------|------------------------------------------------|-----------------------------------------|
|الاسم |مطلوب + اسم ثلاثي على الأقل (3 كلمات)           |“يجب إدخال الاسم الثلاثي على الأقل”      |
|الاسم |كشف التكرار ضد الأعضاء الموجودين                |“يوجد عضو بنفس الاسم — هل تريد المتابعة؟”|
|الجوال|صيغة `05xxxxxxxx` (10 أرقام تبدأ بـ 05) إذا أُدخل|“صيغة رقم الجوال غير صحيحة”              |
|الجوال|كشف التكرار ضد الأرقام الموجودة                 |“يوجد عضو بنفس رقم الجوال”               |

**سلوك التحقق:**

- رسائل خطأ واضحة تحت كل حقل (inline errors)
- تلوين الحقل الخاطئ بحدود حمراء
- عند وجود تكرار: تنبيه مع **خيار المتابعة** (ليس منع تام)
- منع الحفظ فقط عند وجود أخطاء إلزامية (الاسم أقل من ثلاثي / صيغة جوال خاطئة)

**أمثلة التحقق من الاسم:**

- ❌ `"علي العوامي"` — ثنائي، لا يُقبل
- ✅ `"علي عماد العوامي"` — ثلاثي، مقبول
- ✅ `"علي عماد علي العوامي"` — رباعي، مقبول

## 11. معايير القبول

### 11.1 الاستيراد من Excel

- استيراد ملف Excel يحفظ البيانات فعلياً في قاعدة البيانات
- البيانات تبقى بعد تحديث الصفحة وعند الدخول من جهاز آخر
- خطوة المراجعة تظهر قبل الحفظ مع إمكانية التعديل والحذف
- شريط التقدم يظهر أثناء الحفظ
- `saveDB()` غير مُستدعى في ملف الاستيراد

### 11.2 زر الحفظ

- الضغط على “حفظ” يعمل دائماً — لا يتجمد
- حالة loading واضحة (spinner) أثناء الحفظ
- رسالة نجاح أو خطأ واضحة بعد الحفظ

### 11.3 حالات العضوية

- الحالات الجديدة (مشترك / منقطع / غير مشترك) تظهر في كل الواجهات
- حالة “معفي” غير موجودة في أي مكان بالنظام
- قواعد الحساب التلقائي تعمل بالحالات الجديدة
- البيانات الموجودة مُرحّلة بشكل صحيح

### 11.4 نافذة إضافة العضو

- حقلا رقم الهوية والفرع العائلي غير ظاهرين
- التحقق من صيغة الجوال يعمل
- كشف التكرار يعمل مع خيار المتابعة
- رسائل الخطأ واضحة تحت كل حقل

### 11.5 الجدول والبحث

- الـ badges بالألوان الجديدة
- زر إعادة ضبط الفلاتر يعمل
- العرض على الموبايل سليم
