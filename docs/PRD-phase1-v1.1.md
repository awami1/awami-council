# وثيقة متطلبات المنتج (PRD)

## المرحلة الأولى — مشروع: alawami.site

### نظام هوية الأعضاء والصفحة الشخصية

- **الإصدار:** 1.1
- **التاريخ:** مارس 2026
- **المشروع:** الموقع الرسمي لعائلة العوامي
- **المسؤول:** عبدالله (مجلس عائلة العوامي)
- **الحالة:** قيد المراجعة

## 1. نظرة عامة

### 1.1 الهدف

بناء نظام هوية رقمية لأعضاء مجلس عائلة العوامي، يتيح لكل عضو الوصول إلى صفحته الشخصية التي تتضمن سجله الكامل من عضوية في اللجان، حالة الاشتراكات، والمدفوعات — مع إمكانية طباعة تقرير رسمي وتقديم ملاحظات واعتراضات.

### 1.2 المشكلة الحالية

- لا يوجد حالياً أي آلية لدخول الأعضاء للموقع
- الوصول مقتصر على المدير فقط عبر لوحة التحكم
- الأعضاء لا يستطيعون الاطلاع على سجلاتهم الشخصية بشكل مستقل
- حالة العضوية تُحدث يدوياً دون آلية محاسبة واضحة

### 1.3 الحل

طبقة مصادقة مستقلة للأعضاء فوق البنية التحتية القائمة، مع صفحة شخصية شاملة وآلية حالة تلقائية ذكية.

### 1.4 المستخدمون المستهدفون

|الفئة                     |الوصف                                               |
|--------------------------|----------------------------------------------------|
|أفراد العائلة داخل المملكة|أعضاء نشطون يتابعون اشتراكاتهم ومشاركاتهم           |
|أبناء العائلة في الخارج   |يريدون البقاء على تواصل وتتبع سجلاتهم عن بُعد        |
|مدير الموقع               |يدير الحسابات، يراجع الاعتراضات، يؤكد تغييرات الحالة|

## 3. التعديلات على قاعدة البيانات

### 3.1 جدول جديد: member_users

جدول مستقل لبيانات دخول الأعضاء، مفصول عن جدول members الأصلي.

```sql
CREATE TABLE member_users (
  id VARCHAR(36) NOT NULL PRIMARY KEY, -- UUID
  member_id VARCHAR(36) NOT NULL UNIQUE, -- FK → members.id
  awm_id VARCHAR(10) NOT NULL UNIQUE, -- AWM-0001
  password_hash VARCHAR(255) NOT NULL,
  first_login TINYINT(1) DEFAULT 1, -- 1 = يجب تغيير الكلمة
  temp_token VARCHAR(100) DEFAULT NULL, -- رمز التفعيل المؤقت
  token_expiry DATETIME DEFAULT NULL, -- صلاحية 48 ساعة
  last_login DATETIME DEFAULT NULL,
  is_active TINYINT(1) DEFAULT 0, -- 0 = لم يُفعَّل بعد
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  FOREIGN KEY (member_id) REFERENCES members(id) ON DELETE CASCADE
);
```

**ملاحظات:**

- `awm_id` يتولد تلقائياً بالتسلسل: AWM- + 4 أرقام مرقم
- `temp_token` يُحذف بعد أول دخول ناجح
- `first_login = 1` يُجبر العضو على تغيير كلمة السر فور الدخول

### 3.2 تعديل جدول members

```sql
-- إضافة 'منقطع' لقيم الحالة
ALTER TABLE members
MODIFY COLUMN status ENUM('نشط', 'منقطع', 'معفي', 'غير نشط') DEFAULT 'نشط';

-- حقل لتحديد إذا كانت الحالة يدوية أو تلقائية
ALTER TABLE members
ADD COLUMN status_override TINYINT(1) DEFAULT 0
COMMENT '1 = حالة يدوية بواسطة المدير، 0 = محسوبة تلقائياً';

-- حقل لسبب التجاوز اليدوي
ALTER TABLE members
ADD COLUMN status_override_note VARCHAR(300) DEFAULT NULL;
```

### 3.3 تعديل جدول committee_members

```sql
-- إضافة دعم للأرشفة التاريخية
ALTER TABLE committee_members
ADD COLUMN start_year YEAR DEFAULT NULL,
ADD COLUMN end_year YEAR DEFAULT NULL
COMMENT 'NULL = عضوية حالية';

-- إضافة دور العضو في اللجنة
ALTER TABLE committee_members
ADD COLUMN role VARCHAR(100) DEFAULT NULL
COMMENT 'مثال: رئيس، نائب، أمين صندوق، عضو';
```

**المنطق:**

- `end_year = NULL` → عضوية حالية نشطة
- `end_year = 2024` → عضوية منتهية (أرشيف)

### 3.4 جدول جديد: member_objections

```sql
CREATE TABLE member_objections (
  id VARCHAR(36) NOT NULL PRIMARY KEY,
  member_id VARCHAR(36) NOT NULL,
  subject VARCHAR(200) NOT NULL,
  body TEXT NOT NULL,
  related_to ENUM('دفعة', 'لجنة', 'بيانات', 'أخرى') DEFAULT 'أخرى',
  related_id VARCHAR(36) DEFAULT NULL, -- الكيان المعترض عليه ID
  status ENUM('جديد', 'قيد المراجعة', 'تمت المعالجة', 'مرفوض') DEFAULT 'جديد',
  admin_reply TEXT DEFAULT NULL,
  replied_at DATETIME DEFAULT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  FOREIGN KEY (member_id) REFERENCES members(id) ON DELETE CASCADE
);
```

## 4. منطق حساب حالة العضوية

### 4.1 القواعد الأساسية

|الحالة المقترحة|الشرط                          |
|---------------|-------------------------------|
|✅ نشط          |دفع آخر فترتين متتاليتين       |
|⚠️ منقطع        |انقطاع فترتين متتاليتين بالضبط |
|❌ غير نشط      |انقطاع أكثر من فترتين متتاليتين|
|🔒 معفي         |معفي (مُعيَّن يدوياً)              |

**الفترة = 6 أشهر، قيمة الاشتراك الحالية = 300 ريال**

### 4.2 آلية التحديث التلقائي

عند إنشاء فترة جديدة:

1. النظام يحسب حالة كل عضو بناءً على سجل دفعاته
1. يُقارن الحالة المحسوبة بالحالة الحالية
1. إذا وُجد فرق → يُنشئ قائمة “تغييرات مقترحة”
1. يُرسل تنبيهاً للمدير في لوحة التحكم
1. المدير يراجع القائمة ويؤكد أو يتجاوز كل حالة
1. عند التجاوز اليدوي → يُسجَّل السبب في status_override_note

### 4.3 الأولوية

حساب تلقائي < status_override = 1 > معفي (يدوي)

إذا `status_override = 1` → النظام لا يقترح تغييراً على هذا العضو حتى يُلغي المدير التجاوز يدوياً.

## 5. نظام الهوية والدخول

### 5.1 توليد AWM-ID

- الصيغة: `AWM-[رقم تسلسلي من 4 أرقام]`
- أمثلة: AWM-0001، AWM-0042، AWM-0150
- يتولد تلقائياً عند تفعيل الحساب
- مرئي للعضو في صفحته الشخصية
- يُستخدم لتسجيل الدخول
- لا يتغير أبداً بعد الإنشاء

### 5.2 مراحل التفعيل

**المرحلة ١ — المدير:**

- يفتح ملف العضو في لوحة التحكم
- يضغط “تفعيل حساب”
- يتولد: AWM-ID + رمز مؤقت (8 أحرف عشوائية) صالح 48 ساعة
- يُعرض رسالة واتساب جاهزة بالمعلومات

**المرحلة ٢ — رسالة الواتساب:**

```
مرحباً [اسم العضو]

تم تفعيل حسابك في موقع
عائلة العوامي

رقم العضوية: AWM-XXXX
رمز الدخول الأول: XXXXXXXX

رابط الدخول: alawami.site/login

الرمز صالح لمدة 48 ساعة
سيُطلب منك تغيير كلمة السر فور الدخول الأول
```

**المرحلة ٣ — العضو:**

- يفتح الرابط ويُدخل AWM-ID + الرمز المؤقت
- يُجبَر على إنشاء كلمة سر جديدة (8 أحرف+)
- يدخل للصفحة الشخصية مباشرة

### 5.3 نقاط API الجديدة

|الطريقة|المسار                       |الوصف                                     |
|-------|-----------------------------|------------------------------------------|
|POST   |/api/auth/member-login.php   |تسجيل دخول بـ AWM-ID + كلمة سر            |

## 8. نظام الاعتراضات

### 8.1 مسار الاعتراض من جانب العضو

1. العضو يضغط “تقديم ملاحظة أو اعتراض”
1. يختار نوع الاعتراض: دفعة / لجنة / بيانات / أخرى
1. يكتب الموضوع والتفاصيل
1. يضغط إرسال
1. يصله تأكيد: “تم استلام ملاحظتك، سيتم الرد خلال X أيام”

### 8.2 مسار الاعتراض من جانب المدير

1. يصل إشعار في لوحة التحكم (قسم الرسائل الحالي)
1. يُرسل إيميل تنبيه للمدير: AWM-ID + اسم العضو + الموضوع
1. المدير يفتح الاعتراض، يراجعه، يغيّر الحالة
1. يكتب رداً
1. يُحفظ الرد ويظهر للعضو في صفحته

### 8.3 حالات الاعتراض

## 10. آلية جلسة الأعضاء (Member Session)

### 10.1 القرار التقني

**الآلية المعتمدة:** PHP Session مع session_name منفصل

|البديل              |السبب                                                   |
|--------------------|--------------------------------------------------------|
|✅ PHP Session منفصل |بسيط وموثوق — (Vanilla PHP) متسق مع بنية المشروع الحالية|
|❌ JWT Token         |يضيف تعقيداً غير مبرر لهذا الحجم — يحتاج مكتبة خارجية    |
|❌ نفس session الأدمن|خطر تعارض الصلاحيات                                     |

### 10.2 التطبيق

```php
// ===== جلسة الأدمن (موجودة — لا تُعدَّل) =====
session_name('awami_admin');
session_start();

// ===== جلسة الأعضاء (جديدة) =====
session_name('awami_member');
session_start();

$_SESSION['member_id'] = 'uuid-xxxx';      // UUID الداخلي
$_SESSION['awm_id']    = 'AWM-0042';       // معرف العرض
$_SESSION['name']      = 'اسم العضو';
$_SESSION['expires_at'] = time() + 86400;  // 24 ساعة
```

### 10.3 دالة التحقق requireMemberAuth()

تُنشأ في ملف مستقل `/api/auth/member-guard.php` وتُضمَّن في كل API endpoint خاص بالأعضاء:

```php
function requireMemberAuth(): array {
    session_name('awami_member');
    session_start();

    // التحقق من وجود الجلسة
    if (empty($_SESSION['member_id'])) {
        http_response_code(401);
        echo json_encode(['error' => 'غير مصرح — يرجى تسجيل الدخول']);
        exit;
    }

    // التحقق من انتهاء الصلاحية
    if ($_SESSION['expires_at'] < time()) {
        session_destroy();
        http_response_code(401);
        echo json_encode(['error' => 'انتهت الجلسة — يرجى تسجيل الدخول مجدداً']);
        exit;
    }

    // تجديد الصلاحية عند كل طلب
    $_SESSION['expires_at'] = time() + 86400;

    return [
        'member_id' => $_SESSION['member_id'],
        'awm_id'    => $_SESSION['awm_id'],
        'name'      => $_SESSION['name'],
    ];
}
```

### 10.4 تطبيقها على نقاط API

كل endpoint خاص بالأعضاء يبدأ بـ:

```php
<?php
require_once '../auth/member-guard.php';
$member = requireMemberAuth();
// ثم يستخدم $member['member_id'] في كل استعلامات قاعدة البيانات
```

|نقطة API           |تستخدم requireMemberAuth()؟|
|-------------------|---------------------------|
|member-login.php   |❌ (هي نقطة الدخول نفسها)   |
|activate.php       |❌ (قبل إنشاء الجلسة)       |
|forgot-password.php|❌ (نقطة عامة — بدون مصادقة)|
|change-password.php|✅                          |
|member-logout.php  |✅                          |
|profile.php        |✅                          |
|report.php         |✅                          |
|objection.php      |✅                          |

### 10.5 تسجيل الخروج

```php
// member-logout.php
session_name('awami_member');
session_start();
session_unset();
session_destroy();
header('Location: /login');
exit;
```

## 13. معايير القبول

### 13.1 نظام الدخول

- المدير يقدر يفعّل حساب أي عضو من لوحة التحكم
- AWM-ID يتولد فريد لكل عضو بالتسلسل
- رسالة الواتساب الجاهزة تظهر فور التفعيل
- الرمز المؤقت ينتهي بعد 48 ساعة
- العضو يُجبر على تغيير كلمة السر عند أول دخول
- 5 محاولات فاشلة تؤدي لقفل مؤقت

### 13.2 الصفحة الشخصية

- تُعرض بيانات العضو الكاملة بدقة
- اللجان الحالية والسابقة تظهر بشكل صحيح مع السنوات
- سجل الاشتراكات يعرض كل الفترات مع حالتها
- ملخص مالي (مجموع مدفوع / نسبة الالتزام) صحيح

### 13.3 منطق الحالة

- الحالة تُحسب تلقائياً عند إنشاء فترة جديدة
- قائمة التغييرات المقترحة تظهر للمدير
- المدير يقدر يؤكد أو يتجاوز كل حالة
- status_override = 1 يُعطل الحساب التلقائي

### 13.4 تقرير PDF

- PDF يحتوي شعار المجلس وكل بيانات العضو
- العربية RTL تظهر بشكل صحيح
- ألوان وخطوط متسقة مع هوية الموقع

### 13.5 نظام الاعتراضات

- العضو يقدر يرسل اعتراض من صفحته
- الاعتراض يظهر في لوحة التحكم فوراً
- يُرسل إيميل تنبيه للمدير
- المدير يقدر يرد والعضو يشوف الرد
