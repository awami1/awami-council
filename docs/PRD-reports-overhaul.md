## 1. نظرة عامة

صفحة “التقارير الذكية” الحالية تحتاج إعادة بناء كاملة لتصبح **مركز تقارير** يخدم ثلاث وظائف:

|التبويب          |الوظيفة                                           |المستخدم الرئيسي             |
|-----------------|--------------------------------------------------|-----------------------------|
|① تقارير تلقائية |توليد تقارير فورية من بيانات النظام               |الإدارة + الاجتماعات + واتساب|
|② استيراد معاملات|رفع Excel ← مراجعة يدوية ← إدخال في النظام ← أرشفة|الإدارة (إدخال بيانات)       |
|③ أرشيف التقارير |حفظ وتصنيف ملفات ووثائق مالية للرجوع إليها        |الإدارة (أرشفة)              |

**الكود القديم:** يُحذف محرك التصنيف التلقائي (`smartCategorize`) بالكامل. يُعاد استخدام البنية الأساسية (رفع الملف + قراءة SheetJS + معاينة الجدول + المزامنة مع `transactions.php?bulk=1`) مع مراجعة يدوية كاملة بدل التصنيف الآلي.

-----

## 2. المشكلة

- **بيانات مالية خارج النظام**: الإدارة عندها ملفات Excel قديمة وكشوفات حسابات لم تُدخل في نظام الميزانية — ولا يوجد طريقة سهلة لإدخالها.
- **لا توجد تقارير تلقائية**: رغم وجود بيانات غنية في النظام، التقرير المالي يُحسب يدوياً.
- **لا يوجد أرشيف مركزي**: الملفات متفرقة في أجهزة الإدارة.
- **النصوص مضللة**: الصفحة تدّعي “ذكاء اصطناعي” بينما هي keyword matching.

## 4. التبويب ①: التقارير التلقائية

تقارير تُولَّد فوراً بضغطة زر من بيانات النظام الفعلية. لا تحتاج جداول جديدة — تسحب من الموجود وتُجمّع بـ SQL.

### 4.1 أنواع التقارير

#### أ) الملخص التنفيذي

أهم الأرقام من كل مكان في صفحة واحدة — الأنسب للعرض في الاجتماعات والمشاركة.

**يسحب من:** كل الجداول

**المحتوى:**

- رصيد الصندوق (إيرادات − مصروفات)
- نسبة تحصيل الاشتراكات
- عدد الأعضاء (مشترك / منقطع / غير مشترك)
- ملخص عُهَد اللجان (جدول مختصر)
- الفعاليات القادمة

#### ب) التقرير المالي الشامل

**يسحب من:** `transactions` + `payments` + `periods` + `committees`

**المحتوى:**

- ملخص الصندوق: إجمالي إيرادات، إجمالي مصروفات، صافي الرصيد
- تفصيل الإيرادات حسب الفئة (GROUP BY category WHERE type = ‘إيراد’)
- تفصيل المصروفات حسب الفئة (GROUP BY category WHERE type = ‘مصروف’)
- عُهَد اللجان: لكل لجنة → الميزانية − المصروف الفعلي = الرصيد المتبقي
- ملخص الاشتراكات: المستحق مقابل المحصّل
- بنود يدوية اختيارية (حقول إدخال للأرقام غير الموجودة في النظام)

#### ج) تقرير الاشتراكات

**يسحب من:** `members` + `payments` + `periods`

**المحتوى:**

- إحصائيات الأعضاء حسب الحالة
- لكل فترة مالية: عدد من دفع / لم يدفع / نسبة الالتزام
- قائمة المتخلفين عن الدفع (اسم + فترة + المبلغ)

#### د) تقرير اللجان

**يسحب من:** `committees` + `committee_members` + `transactions` + `events`

**المحتوى:**

- لكل لجنة: الأعضاء، الميزانية، المصروف، الرصيد، عدد الفعاليات

#### هـ) تقرير الفعاليات

**يسحب من:** `events` + `committees`

**المحتوى:**

- الفعاليات حسب الحالة (قادم / جاري / مكتمل / ملغي)
- لكل فعالية: الاسم، التاريخ، اللجنة، الميزانية، المشاركين

### 4.2 الفلاتر المشتركة

- نطاق زمني: من ___ إلى ___
- لجنة: [الكل ▼] أو لجنة محددة
- فترة مالية: [الكل ▼] أو فترة محددة

### 4.3 المخرجات

- عرض مباشر (بطاقات إحصائية + جداول)
- تصدير PDF رسمي بتصميم المجلس
- طباعة مباشرة
- حفظ في الأرشيف (يُنشئ سجل في أرشيف التقارير تلقائياً)

### 4.4 البنود اليدوية (في التقرير المالي فقط)

حقول لإضافة أرقام غير موجودة في النظام:

- حقل “البند” (نص)
- حقل “المبلغ” (رقم)
- حقل “النوع” (إيراد / مصروف)
- زر “+ إضافة بند”

تظهر في التقرير تحت عنوان “بنود إضافية (إدخال يدوي)” ولا تُضاف لقاعدة البيانات — تظهر في التقرير والـ PDF فقط.

## 5. التبويب ②: استيراد معاملات من Excel

### 5.1 الهدف

إدخال معاملات مالية من ملفات Excel/CSV قديمة أو جديدة إلى نظام الميزانية (`transactions`) مع مراجعة يدوية كاملة قبل الإدخال، ثم أرشفة الملف الأصلي تلقائياً.

### 5.2 سير العمل (4 خطوات)

```
  ┌──────┐     ┌──────┐     ┌──────┐     ┌──────┐
  │  ①   │────▶│  ②   │────▶│  ③   │────▶│  ④   │
  │ رفع  │     │ ربط  │     │مراجعة│     │إدخال │
  │الملف │     │الأعمدة│    │وتعديل│     │وأرشفة│
  └──────┘     └──────┘     └──────┘     └──────┘
```

#### الخطوة ①: رفع الملف

- نفس منطقة السحب والإفلات الحالية (drag & drop)
- يدعم: xlsx, xls, csv
- الحد الأقصى: 10 ميجابايت
- يُقرأ بـ SheetJS (نفس الكود الحالي)
- إذا كان فيه أكثر من sheet → يختار المستخدم

```
┌─────────────────────────────────────┐
│                                       │
│    📊  اسحب ملف Excel هنا           │
│        أو انقر للاختيار              │
│                                       │
│    يدعم: .xlsx, .xls, .csv          │
│    (حد أقصى 10 ميجابايت)            │
│                                       │
└─────────────────────────────────────┘
```

#### الخطوة ②: ربط الأعمدة

بعد قراءة الملف، يُعرض:

- اسم الملف وعدد الصفوف
- معاينة أول 3-5 صفوف
- dropdown لكل عمود مطلوب:

|الحقل                   |مطلوب|ملاحظة                           |
|------------------------|-----|---------------------------------|
|عمود الوصف/البيان       |نعم  |                                 |
|عمود المبلغ             |نعم  |                                 |
|عمود التاريخ            |لا   |إذا فارغ → يستخدم تاريخ اليوم    |
|عمود النوع (إيراد/مصروف)|لا   |إذا فارغ → يُحدد يدوياً في الخطوة ③|

**الكشف التلقائي:** نفس منطق `srAutoDetectColumns()` الحالي — يبحث في أسماء الأعمدة عن كلمات مثل “الوصف”، “المبلغ”، “التاريخ”، “النوع” ويحدد الأعمدة مبدئياً. المستخدم يقدر يغيّر.

```
┌─────────────────────────────────────────────┐
│  📄 ملف: كشف_حساب_2025.xlsx               │
│  📋 عدد الصفوف: 45                          │
│                                               │
│  ── ربط الأعمدة ──                           │
│  عمود الوصف:   [البيان          ▼]           │
│  عمود المبلغ:   [المبلغ          ▼]           │
│  عمود التاريخ:  [تاريخ العملية    ▼]           │
│  عمود النوع:    [— لا يوجد —     ▼]           │
│                                               │
│  ── معاينة ──                                │
│  │ التاريخ   │ البيان        │ المبلغ │       │
│  │ 2025/01/5 │ اشتراك أحمد  │ 200   │       │
│  │ 2025/01/7 │ ضيافة اجتماع │ 350   │       │
│  │ 2025/01/10│ تبرع خالد    │ 500   │       │
│                                               │
│  [→ التالي: مراجعة المعاملات]                │
└─────────────────────────────────────────────┘
```

#### الخطوة ③: مراجعة وتعديل يدوي

**هنا الفرق الجوهري عن النظام القديم**: بدل التصنيف التلقائي، كل صف يظهر بحقول **قابلة للتعديل مباشرة** في الجدول.

**الجدول:**

|✓|التاريخ   |الوصف       |المبلغ|النوع ▼  |الفئة ▼     |اللجنة ▼|
|-|----------|------------|------|---------|------------|--------|
|☑|2025/01/05|اشتراك أحمد |200   |[إيراد ▼]|[اشتراكات ▼]|[— ▼]   |
|☑|2025/01/07|ضيافة اجتماع|350   |[مصروف ▼]|[ضيافة ▼]   |[— ▼]   |
|☐|2025/01/08|???         |0     |[— ▼]    |[— ▼]       |[— ▼]   |
|☑|2025/01/10|تبرع خالد   |500   |[إيراد ▼]|[تبرعات ▼]  |[— ▼]   |

**لكل صف:**

- **checkbox**: لاختيار الصفوف المراد إدخالها (الصفوف الفارغة أو المبلغ = 0 تكون غير محددة افتراضياً)
- **التاريخ**: قابل للتعديل
- **الوصف**: قابل للتعديل (نص)
- **المبلغ**: قابل للتعديل (رقم)
- **النوع**: dropdown — إيراد / مصروف (مطلوب)
- **الفئة**: dropdown — نفس فئات الميزانية الموجودة (اشتراكات، تبرعات، ضيافة، مصاريف إدارية، فعاليات، رواتب، إيجار، مرافق، نقل، إعلام، هدايا، تعليم، رحلات، مناسبات، أخرى) + خيار “بدون فئة”
- **اللجنة**: dropdown — قائمة اللجان من النظام + “عام”

**إجراءات جماعية:**

- تحديد الكل / إلغاء الكل
- تعيين النوع لكل المحدد: [إيراد ▼] [تطبيق]
- تعيين الفئة لكل المحدد: [اشتراكات ▼] [تطبيق]
- تعيين اللجنة لكل المحدد: [لجنة العيدين ▼] [تطبيق]
- حذف المحدد

**ملخص سفلي (يتحدث حسب التعديلات):**

```
محدد: 42 من 45  |  إيرادات: 12,500 ريال  |  مصروفات: 8,200 ريال  |  صافي: +4,300 ريال
```

**التحقق قبل المتابعة:**

- كل صف محدد لازم يكون عنده نوع (إيراد/مصروف)
- المبلغ لازم يكون > 0
- إذا فيه صفوف ناقصة → تنبيه أصفر يوضح أي صفوف تحتاج تكملة

#### الخطوة ④: إدخال في النظام + أرشفة

**تأكيد:**

```
┌─────────────────────────────────────┐
│  ⚠️  تأكيد الإدخال                  │
│                                       │
│  سيتم إدخال 42 معاملة في النظام:    │
│  • إيرادات: 25 معاملة (12,500 ريال)  │
│  • مصروفات: 17 معاملة (8,200 ريال)   │
│                                       │
│  الملف الأصلي سيُحفظ في الأرشيف.     │
│                                       │
│  [إدخال في النظام]    [رجوع للمراجعة] │
└─────────────────────────────────────┘
```

**عند التأكيد:**

1. إرسال المعاملات المحددة إلى `POST /api/transactions.php?bulk=1`
1. حفظ مرجع الملف تلقائياً في أرشيف التقارير:
- العنوان: “استيراد: [اسم الملف]”
- النوع: “كشف حساب”
- التاريخ: تاريخ اليوم
- الوصف: “تم استيراد [42] معاملة من هذا الملف”
- الرابط: (فارغ مرحلياً — أو رابط إذا كان الملف على Drive)
1. عرض نتيجة:

```
┌─────────────────────────────────────┐
│  ✅ تم بنجاح!                        │
│                                       │
│  • تم إدخال: 42 معاملة               │
│  • تكرارات تم تجاهلها: 3             │
│  • الملف محفوظ في الأرشيف            │
│                                       │
│  [📊 عرض الميزانية]  [📥 استيراد آخر] │
```

## 7. المتطلبات التقنية

### 7.1 APIs جديدة

#### أ) `api/report-generator.php` — توليد التقارير التلقائية

|Method|Parameters           |الوصف                |
|------|---------------------|---------------------|
|GET   |`?type=summary`      |الملخص التنفيذي      |
|GET   |`?type=financial`    |التقرير المالي الشامل|
|GET   |`?type=subscriptions`|تقرير الاشتراكات     |
|GET   |`?type=committees`   |تقرير اللجان         |
|GET   |`?type=events`       |تقرير الفعاليات      |

**Parameters مشتركة:** `date_from`, `date_to`, `committee_id`, `period_id`

لا يحتاج جدول جديد — يستخدم SQL aggregation على الجداول الموجودة.

#### ب) `api/report-archive.php` — أرشيف التقارير (CRUD)

|Method|المسار                        |الوصف                                                                  |
|------|------------------------------|-----------------------------------------------------------------------|
|GET   |`/api/report-archive.php`     |قائمة (?type, ?date_from, ?date_to, ?committee_id, ?period_id, ?search)|
|GET   |`/api/report-archive.php?id=X`|تقرير واحد                                                             |
|POST  |`/api/report-archive.php`     |إضافة                                                                  |
|PUT   |`/api/report-archive.php?id=X`|تعديل                                                                  |
|DELETE|`/api/report-archive.php?id=X`|حذف                                                                    |

#### ج) `api/report-pdf.php` — تصدير PDF

|Method|Parameters                                               |الوصف       |
|------|---------------------------------------------------------|------------|
|GET   |`?type=summary|financial|subscriptions|committees|events`|يُعيد ملف PDF|

- نفس فلاتر report-generator + حقل `extra_items` (JSON) للبنود اليدوية.

يستخدم TCPDF بنفس تصميم report.php (رأس أزرق، خط ذهبي، تذييل رسمي).

### 7.2 جدول قاعدة بيانات جديد

```sql
-- MySQL
CREATE TABLE `report_archive` (
    `id` VARCHAR(36) NOT NULL,
    `title` VARCHAR(300) NOT NULL,
    `report_type` ENUM('مالي','إداري','محضر اجتماع','كشف حساب','أخرى') NOT NULL DEFAULT 'أخرى',
    `source` ENUM('manual','import','generated') NOT NULL DEFAULT 'manual',
    `description` TEXT,
    `file_url` VARCHAR(500) DEFAULT NULL,
    `file_type` VARCHAR(20) DEFAULT NULL,
    `report_date` DATE NOT NULL,
    `period_id` VARCHAR(36) DEFAULT NULL,
    `committee_id` VARCHAR(36) DEFAULT NULL,
    `import_stats` JSON DEFAULT NULL,
    `status` ENUM('active','archived') NOT NULL DEFAULT 'active',
    `created_by` VARCHAR(36) DEFAULT NULL,
    `created_at` TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updated_at` TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    INDEX `idx_archive_type` (`report_type`),
    INDEX `idx_archive_date` (`report_date`),
    INDEX `idx_archive_source` (`source`),
    INDEX `idx_archive_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- SQLite
CREATE TABLE IF NOT EXISTS report_archive (
    id VARCHAR(36) NOT NULL PRIMARY KEY,
    title VARCHAR(300) NOT NULL,
    report_type TEXT NOT NULL DEFAULT 'أخرى'
        CHECK(report_type IN ('مالي','إداري','محضر اجتماع','كشف حساب','أخرى')),
    source TEXT NOT NULL DEFAULT 'manual'
        CHECK(source IN ('manual','import','generated')),
    description TEXT,
    file_url VARCHAR(500) DEFAULT NULL,
    file_type VARCHAR(20) DEFAULT NULL,
    report_date DATE NOT NULL,
    period_id VARCHAR(36) DEFAULT NULL,
    committee_id VARCHAR(36) DEFAULT NULL,
    import_stats TEXT DEFAULT NULL,
    status TEXT NOT NULL DEFAULT 'active' CHECK(status IN ('active','archived')),
    created_by VARCHAR(36) DEFAULT NULL,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

**حقل `source`:** يميّز مصدر التقرير:

- `manual` — مرفوع يدوياً من المستخدم
- `import` — أُنشئ تلقائياً عند استيراد معاملات من Excel
- `generated` — أُنشئ من تقرير تلقائي تم حفظه

**حقل `import_stats`:** (JSON) يحفظ إحصائيات الاستيراد:

```json
{
  "file_name": "كشف_حساب_2025.xlsx",
  "total_rows": 45,
  "imported": 42,
  "skipped": 3,
  "total_income": 12500,
  "total_expense": 8200,
  "imported_at": "2026-03-21T10:00:00"
}
```

- `srPrintReport()` — طباعة (يُستبدل بطباعة جديدة)

**يُعاد استخدامه (مع تعديل):**

- `srProcessFile()` → تبقى لقراءة الملف بـ SheetJS
- `srShowPreview()` → تبقى لعرض المعاينة
- `srAutoDetectColumns()` → تبقى للكشف التلقائي عن أسماء الأعمدة
- `srCleanData()` → تبقى لتنظيف البيانات
- `handleAIFileUpload()` + drag/drop handlers → تبقى مع تغيير الأسماء
- `syncAIDataToDB()` → تُعدَّل لتصبح دالة الإدخال النهائي (بدون تصنيف تلقائي)
- `srApplyBulkEdit()` → تُعدَّل للتعديل الجماعي الجديد
- `srDeleteSelected()` → تبقى
- `downloadAIReport()` → تُحذف (يُستبدل بتصدير PDF)

**المتغيرات:**

- `aiAnalysisData` → يُعاد تسميته لـ `importData` أو ما يناسب
- `srWorkbook`, `srRawData`, `srFileName` → تبقى
- `srSelectedRows` → تبقى

### 7.5 لا تعديل على

- `api/reports.php` — يبقى للبيانات القديمة
- `api/transactions.php` — يُستخدم `?bulk=1` كما هو
- باقي الـ APIs — تُقرأ منها فقط
