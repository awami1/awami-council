# وثيقة متطلبات المنتج (PRD)

## مشروع: alawami.site — تحسين صفحة إدارة الأعضاء

**الإصدار:** 1.0  
**التاريخ:** مارس 2026  
**المشروع:** الموقع الرسمي لعائلة العوامي  
**المسؤول:** عبدالله (مجلس عائلة العوامي)  
**الحالة:** قيد المراجعة

-----

## 1. نظرة عامة

### 1.1 الهدف

تحسين صفحة إدارة الأعضاء في لوحة التحكم لتكون أكثر كفاءة في العرض والتنظيف والإدارة الجماعية، مع دعم متساوٍ للاستخدام من الجوال والكمبيوتر.

### 1.2 المشكلة الحالية

- **عرض غير مرن:** الصفحة تعرض كل عضو كبطاقة عمودية طويلة (card) بغض النظر عن حجم الشاشة، مما يصعّب المقارنة والاستعراض السريع على الشاشات الكبيرة.
- **غياب الرؤية الإحصائية:** لا يوجد ملخص فوري لتوزيع الأعضاء حسب الحالة أو حالة الحسابات — المدير يضطر للفلترة يدوياً لمعرفة الأرقام.
- **تكرار البيانات:** يوجد أكثر من 100 عضو، تقريباً نصفهم مكررون (نسخ مطابقة بالاسم). حذفهم يتم واحداً واحداً حالياً وهذا غير عملي.
- **محدودية الإجراءات:** لا يوجد حذف جماعي أو تعديل جماعي للحالة — كل عملية تتم على عضو فردي.
- **الترتيب ثابت:** لا يمكن ترتيب الأعضاء إلا أبجدياً بالاسم (الترتيب الافتراضي من الـ API).

### 1.3 الحل

إضافة طبقة عرض محسّنة وأدوات تنظيف بيانات داخل صفحة الأعضاء الحالية في لوحة التحكم، دون تغيير البنية التحتية أو الـ API الموجود (إلا ما يتطلبه الحذف الجماعي).

### 1.4 المستخدم المستهدف

|الفئة      |الوصف                                                         |
|-----------|--------------------------------------------------------------|
|مدير الموقع|المستخدم الوحيد — يدير الأعضاء من الجوال والكمبيوتر بشكل متساوٍ|

-----

## 2. نطاق العمل

### 2.1 ما يشمله هذا الـ PRD ✅

- شريط إحصائيات سريع فوق الجدول
- عرضان قابلان للتبديل: بطاقات + جدول مضغوط
- توسيع الصف (accordion) في العرض المضغوط
- ترتيب الأعمدة (sortable columns)
- تحسين تنظيم شريط الفلاتر
- كشف التكرار التلقائي كفلتر
- حذف جماعي (bulk delete)
- تعديل جماعي للحالة (bulk status update)

### 2.2 ما لا يشمله هذا الـ PRD ❌

- تعديل البيانات الأساسية للعضو (الـ modal الحالي كافٍ)
- دمج عضوين مكررين (نقل بيانات من عضو لآخر)
- كشف التكرار بالتشابه الجزئي (مثل إبراهيم/ابراهيم) — المطابقة بالاسم الكامل بالضبط فقط
- تعديلات على الـ API الحالي (إلا endpoint الحذف الجماعي)
- تعديلات على صفحة بوابة العضو أو الموقع العام

-----

## 3. التعديلات على قاعدة البيانات

### 3.1 لا تعديلات على الجداول

لا يتطلب هذا الـ PRD أي تعديلات على بنية قاعدة البيانات. جميع التحسينات تعمل على البيانات الموجودة.

### 3.2 حالات العضوية المعتمدة

الحالات الثلاث المعتمدة فعلياً:

|الحالة   |الوصف                   |اللون       |
|---------|------------------------|------------|
|مشترك    |عضو فعّال يتابع اشتراكاته|أخضر        |
|منقطع    |عضو توقف عن الاشتراك    |برتقالي/أصفر|
|غير مشترك|ليس عضواً فعالاً          |رمادي       |


> **ملاحظة:** حالة “معفي” لم تعد مستخدمة. الفلاتر والإحصائيات تعكس الحالات الثلاث فقط.

-----

## 4. شريط الإحصائيات

### 4.1 الوصف

شريط أفقي يظهر فوق الجدول مباشرة، يعرض ملخصاً رقمياً سريعاً لحالة الأعضاء.

### 4.2 المحتوى

|البطاقة  |البيانات                       |اللون     |
|---------|-------------------------------|----------|
|الإجمالي |عدد الأعضاء الكلي (بعد الفلترة)|أزرق/رمادي|
|مشترك    |عدد المشتركين                  |أخضر      |
|منقطع    |عدد المنقطعين                  |برتقالي   |
|غير مشترك|عدد غير المشتركين              |رمادي     |

### 4.3 السلوك

- الأرقام تتحدث تلقائياً عند تغيير أي فلتر (بحث، حالة، حساب، تكرار)
- البطاقة قابلة للضغط — الضغط عليها يفلتر الجدول بتلك الحالة (كاختصار سريع)
- على الجوال: تُعرض كشريط أفقي قابل للتمرير (scroll) أو شبكة 2×2

-----

## 5. عرضان قابلان للتبديل

### 5.1 الوصف

زر toggle يتيح التبديل بين عرض البطاقات الحالي وعرض جدول مضغوط جديد.

### 5.2 عرض البطاقات (cards) — الحالي

- يبقى كما هو بدون تعديل
- يكون العرض الافتراضي على الشاشات الصغيرة (< 768px)

### 5.3 عرض الجدول المضغوط (compact table) — جديد

- يكون العرض الافتراضي على الشاشات الكبيرة (≥ 768px)
- كل عضو يُعرض في صف أفقي واحد

أعمدة الجدول المضغوط:

|#|العمود|الوصف                                 |
|-|------|--------------------------------------|
|1|#     |الترقيم التسلسلي                      |
|2|العضو |الاسم + العائلة + avatar (الحرف الأول)|
|3|AWM-ID|معرّف العضو (أو “—” إذا بدون حساب)     |
|4|الجوال|رقم الجوال (أو “—”)                   |
|5|اللجان|عدد اللجان أو أسماؤها مختصرة          |
|6|الحالة|badge بلون الحالة                     |
|7|الدفع |حالة الدفع للدورة الحالية             |
|8|الحساب|badge: مفعّل / غير مفعّل / بدون حساب    |

### 5.4 التوسيع (Accordion)

عند الضغط على أي صف في العرض المضغوط، يتوسع ليعرض:

- تاريخ الانضمام
- الملاحظات (إن وجدت)
- أسماء اللجان كاملة مع الأدوار
- أزرار الإجراءات: تعديل، حذف، تفعيل حساب

### 5.5 حفظ الاختيار

- اختيار العرض (بطاقات/جدول) يُحفظ في `localStorage` تحت مفتاح `members-view-mode`
- القيم: `cards` أو `table`

-----

## 6. ترتيب الأعمدة (Sortable)

### 6.1 الأعمدة القابلة للترتيب

|العمود        |الترتيب الافتراضي|الاتجاه                  |
|--------------|-----------------|-------------------------|
|العضو (الاسم) |✅ افتراضي        |أبجدي تصاعدي (أ → ي)     |
|تاريخ الانضمام|—                |الأحدث أول               |
|الحالة        |—                |مشترك → منقطع → غير مشترك|

### 6.2 السلوك

- الضغط الأول: ترتيب تصاعدي
- الضغط الثاني: ترتيب تنازلي
- الضغط الثالث: يعود للترتيب الافتراضي (أبجدي بالاسم)
- سهم صغير (▲/▼) يظهر بجانب عنوان العمود النشط
- الترتيب يعمل على البيانات المفلترة (بعد تطبيق الفلاتر)
- الترتيب يعمل في كلا العرضين (البطاقات والجدول المضغوط)

-----

## 7. تحسين شريط الفلاتر

### 7.1 الوضع الحالي

الفلاتر (بحث + حالة + حساب) معروضة عمودياً فوق بعض.

### 7.2 التحسين

- **على الكمبيوتر (≥ 768px):** صف أفقي واحد يضم: حقل البحث + فلتر الحالة + فلتر الحساب + فلتر التكرار + زر “ضبط” (reset)
- **على الجوال (< 768px):** نفس الترتيب الحالي (عمودي) مع تحسين المسافات
- فلتر الحالة يعرض: كل الحالات / مشترك / منقطع / غير مشترك (3 حالات فقط، بدون “معفي”)

-----

## 8. كشف التكرار التلقائي

### 8.1 الوصف

فلتر جديد يُضاف لشريط الفلاتر الموجود، يعرض الأعضاء المتكررين فقط.

### 8.2 آلية الكشف

- المطابقة تكون بالاسم الكامل بالضبط: `name + ' ' + family` (بعد trim وتوحيد المسافات)
- تُجمع النتائج في مجموعات (groups) — كل مجموعة تحتوي على عضوين أو أكثر لهم نفس الاسم الكامل
- المجموعات تُعرض بلون خلفية مميز (alternating) لتسهيل التمييز بينها

### 8.3 واجهة المستخدم

- في شريط الفلاتر: dropdown أو زر “🔍 المكررين (N)” حيث N = عدد الأعضاء المكررين
- عند التفعيل: الجدول يعرض فقط المجموعات المتكررة
- كل مجموعة تعرض الأعضاء جنب بعض مع كل بياناتهم (تاريخ الانضمام، الجوال، الحالة، الحساب)
- المدير يختار يدوياً أيهم يحذف عبر checkboxes ثم يضغط “حذف المحددين”

### 8.4 ملاحظة

- الكشف يتم في الـ frontend (JavaScript) على البيانات المحمّلة — لا حاجة لـ API جديد
- الأداء مقبول لـ 100-200 عضو بدون مشاكل

-----

## 9. الحذف الجماعي

### 9.1 الوصف

إمكانية تحديد عدة أعضاء وحذفهم دفعة واحدة.

### 9.2 واجهة المستخدم

- checkbox يظهر على كل صف/بطاقة عضو
- في الأعلى: checkbox “تحديد الكل” (يحدد الصفحة الحالية فقط)
- عند تحديد عضو واحد أو أكثر: يظهر شريط إجراءات عائم (floating action bar) في الأسفل يحتوي:
  - عدد المحددين: “تم تحديد X عضو”
  - زر “🗑️ حذف المحددين”
  - زر “📝 تغيير الحالة”
  - زر “✕ إلغاء التحديد”

### 9.3 التأكيد

عند الضغط على “حذف المحددين”:

1. يظهر modal تأكيد يعرض:
- عدد الأعضاء المحددين
- تحذير: “سيتم حذف X عضو نهائياً. هذا الإجراء لا يمكن التراجع عنه.”
- قائمة بأسماء الأعضاء المحددين (أول 10 + “و N آخرين” إذا أكثر)
1. زران: “تأكيد الحذف” (أحمر) + “إلغاء”

### 9.4 التنفيذ التقني

- **API جديد:** `DELETE /api/members.php?action=bulk_delete`
- **Body:** `{ "ids": ["uuid1", "uuid2", ...] }`
- **الحد الأقصى:** 50 عضو بالطلب الواحد
- **السلوك:** حذف بالتتابع داخل transaction واحد
- **التدقيق:** تسجيل عملية واحدة في audit_log بنوع “حذف جماعي” تتضمن عدد وأسماء المحذوفين
- **الاستجابة:** `{ "deleted": 15, "failed": 0, "errors": [] }`

-----

## 10. تعديل جماعي للحالة

### 10.1 الوصف

إمكانية تحديد عدة أعضاء وتغيير حالتهم دفعة واحدة.

### 10.2 واجهة المستخدم

عند الضغط على “📝 تغيير الحالة” من شريط الإجراءات العائم:

1. يظهر modal يعرض:
- عدد الأعضاء المحددين
- dropdown لاختيار الحالة الجديدة (مشترك / منقطع / غير مشترك)
1. زران: “تأكيد التغيير” + “إلغاء”

### 10.3 التنفيذ التقني

- **API جديد:** `PUT /api/members.php?action=bulk_status`
- **Body:** `{ "ids": ["uuid1", "uuid2", ...], "status": "منقطع" }`
- **الحد الأقصى:** 50 عضو بالطلب الواحد
- **التدقيق:** تسجيل عملية واحدة في audit_log بنوع “تعديل حالة جماعي”
- **الاستجابة:** `{ "updated": 15, "failed": 0, "errors": [] }`
